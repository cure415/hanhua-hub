它怎么跑起来的

GitHub Actions 每天两次（北京时间 08:30 / 20:30）执行 node scripts/fetch.js：先读 B站作者的「专栏列表」发现最新「汉化情报汇总」（动态流被 -352 风控时自动降级，正文还有 read/mobile 与 opus 两级兜底），再逐条解析【平台】/ 游戏名 / 汉化发布者 / 发布日期 / 原始视频地址；同时扫 A9VG、Stage1st 新版主题、围炉Go 新汉化栏目，以及 gmerago / CheatMaker / 全机种社区的长帖新增行。结果写回 auto-data.js 与 data/auto.json，重新打包单文件版并提交，Pages 自动部署。

解析出的条目带置信度，低于阈值的只进 data/pending.json 待人工复核，不会直接进公开索引；同名同平台条目会与人工快照去重。抓取只保留发布者原始页面，不采集 ROM / ISO / 网盘直链。本地手动运行：node scripts/fetch.js && node scripts/build.js。

最接近的中文总表

nanL/RetroGamesZH 是一张巨型 Markdown 表（SYS / CRC / NAME / LANG / MAKE / NOTE），覆盖最全，但没有网页界面、没有下载链接、也没有「最新发布」视图。

做得最好的可视化

mariovirgili 的 WSC 三件套：AI 翻译仓库 + 每日自动镜像 WonderSwan_bps_repo + 浏览器里按 CRC32 自动匹配补丁的 wonderswan-web。但只做 WSC，且是英译。

GitHub 上的多数仓库

是「一个游戏 / 一位作者」的发布库：CN_Patches、youxi-hanhua-releases、nge_2_re、srwz-zh 等。结构清晰但彼此孤立。

非 GitHub 的现成站点

dat.emugif.com 模拟游戏中文数据站已有机种浏览、搜索、排序、发布/收录时间区分与 DAT 下载；但偏 ROM 目录管理，且中文汉化的一手发布绝大多数在 B站 / 网盘 / 论坛，不在 GitHub。

所以缺的不是数据，而是「把多源发布动态结构化 + 统一可视化」的这一层 —— 也就是本页面。点卡片可看完整字段与来源，点「录入新发布」或「导入」可持续扩充。
